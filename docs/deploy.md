# 배포 안내 (How's your Christmas)

> 이 문서를 위에서부터 차례로 따라 하면 배포가 끝납니다. (Task 010, 11.27 작성)
> **비밀 값은 이 문서에 적지 않습니다.** 값은 내 컴퓨터의 `.env.local` 파일과 각 서비스의 관리 화면에 있습니다.

## 먼저 알아 둘 말

| 말 | 뜻 |
| --- | --- |
| **배포** | 내 컴퓨터에서만 보이던 서비스를, 누구나 주소로 들어올 수 있게 인터넷에 올리는 일 |
| **Vercel** | Next.js로 만든 서비스를 올려 주는 곳. GitHub에 코드를 올리면(푸시) 자동으로 새로 배포합니다 |
| **환경 변수** | 코드에 직접 적지 않고 따로 넣어 두는 설정값(주소·비밀 키). 내 컴퓨터에서는 `.env.local`, Vercel에서는 설정 화면에 넣습니다 |
| **운영 주소** | 배포된 서비스의 진짜 주소. 아래에서는 `https://<운영주소>`로 적습니다 (예: `https://hows-your-christmas.vercel.app`) |
| **Redirect URL / Callback URL** | 로그인을 마친 사람을 돌려보낼 주소. LINE·카카오·Supabase에 **미리 등록한 주소로만** 돌려보내 줍니다 (한 글자라도 다르면 오류) |

## 1. 코드를 GitHub에 올리기 (커밋·푸시)

지금 Task 006 이후의 코드는 내 컴퓨터에만 있습니다. Vercel은 GitHub의 `main`을 보고 배포하므로 먼저 올려야 합니다.

- Claude에게 "커밋해 줘", "푸시해 줘"라고 요청하면 진행합니다. (요청 없이 자동으로 하지 않습니다)
- 올리기 전 확인: `.env.local`은 `.gitignore`에 들어 있어 올라가지 않습니다.

## 2. Vercel에 환경 변수 넣기

Vercel → 프로젝트 → **Settings → Environment Variables**에서 아래 7개를 넣습니다. 값은 `.env.local`에서 같은 이름의 값을 복사합니다.

| 이름 | 어디서 보는 값인가 | 비밀인가 |
| --- | --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL` | Supabase → Project Settings → API | 공개돼도 됨 |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | Supabase → Project Settings → API Keys (Publishable key) | 공개돼도 됨 |
| `SUPABASE_SECRET_KEY` | Supabase → Project Settings → API Keys (Secret key) | 🔒 **비밀** |
| `LINE_CHANNEL_ID` | LINE Developers → LINE Login 채널 → Basic settings | 공개돼도 됨 |
| `LINE_CHANNEL_SECRET` | LINE Developers → LINE Login 채널 → Basic settings | 🔒 **비밀** |
| `KAKAO_REST_API_KEY` | 카카오 개발자 콘솔 → 앱 키 → REST API 키 | 공개돼도 됨 |
| `KAKAO_CLIENT_SECRET` | 카카오 개발자 콘솔 → 카카오 로그인 → 보안 → Client Secret | 🔒 **비밀** |

- 적용 범위(Environment)는 **Production**에 꼭 체크합니다. (Preview도 쓰려면 함께 체크)
- `.env.local`에 있는 `SUPABASE_DB_PASSWORD`는 **코드가 쓰지 않으므로 넣지 않습니다.**
- ⚠️ 환경 변수를 넣거나 바꾼 뒤에는 **다시 배포(Redeploy)** 해야 적용됩니다. `NEXT_PUBLIC_`으로 시작하는 값은 빌드할 때 코드에 박히기 때문입니다.

## 3. 운영 주소를 누구나 열 수 있게 하기

- Vercel → Settings → **Deployment Protection**이 켜져 있으면, 로그인한 Vercel 계정만 사이트를 열 수 있습니다. 지인이 들어오려면 **운영(Production) 주소는 보호를 꺼야** 합니다.
- 운영 주소는 Vercel → 프로젝트 → **Domains**에서 확인합니다. 배포마다 바뀌는 긴 주소(`...-abc123.vercel.app`)가 아니라 **고정된 주소**를 씁니다.

## 4. 운영 주소를 세 곳에 등록하기

로그인은 "등록된 주소"로만 돌아올 수 있습니다. 운영 주소가 정해지면 아래 세 곳에 넣습니다.

| 어디에 | 무엇을 | 넣을 값 |
| --- | --- | --- |
| **LINE Developers** → LINE Login 채널 → LINE Login 탭 → **Callback URL** | 한 줄 추가 | `https://<운영주소>/auth/line/callback` |
| **카카오 개발자 콘솔** → 카카오 로그인 → **Redirect URI** | 한 줄 추가 | `https://<운영주소>/auth/kakao/callback` |
| **카카오 개발자 콘솔** → 앱 설정 → 플랫폼 → Web → **사이트 도메인** | 한 줄 추가 | `https://<운영주소>` |
| **Supabase** → Authentication → URL Configuration → **Site URL** | 바꾸기 | `https://<운영주소>` |

- 기존의 `http://localhost:...` 줄은 지우지 않습니다. (내 컴퓨터에서 계속 개발하려면 필요)
- 내 컴퓨터에서 카카오 로그인을 해 보려면 Redirect URI에 `http://localhost:3001/auth/kakao/callback`도 넣습니다.
- **카카오 동의항목은 "닉네임" 하나만 켜면 됩니다.** (11.27 변경) 카카오 로그인은 LINE처럼 우리 서버가 카카오와 직접 통신하고 닉네임만 요청합니다. 이메일은 받지 않으므로 **비즈 앱 전환(본인인증)이 필요 없습니다.** Supabase의 Kakao 로그인 설정(Providers → Kakao)은 더 이상 쓰지 않습니다.
- LINE 채널이 **Developing(개발 중)** 상태면 채널 관리자·테스터만 로그인할 수 있습니다. 지인이 로그인하려면 채널을 **Published**로 바꿉니다.
- 카카오는 앱이 **서비스 중** 상태가 아니면 팀원만 로그인할 수 있습니다.

## 5. 배포 후 확인 (순서대로)

1. [ ] 운영 주소를 열면 눈 내리는 첫 화면(로고 + LINE·카카오 버튼)이 나온다
2. [ ] `https://<운영주소>/village/demo`는 첫 화면으로 돌아간다 (연습용 마을은 운영에서 닫혀 있음)
3. [ ] **LINE으로 시작하기** → 로그인 → 마을 만들기 화면
4. [ ] 마을 만들기 → 초대 링크 복사 → 캐릭터 꾸미기 → "이용 방법" 안내가 뜬다
5. [ ] 다른 계정(또는 다른 사람)이 초대 링크로 들어와 **카카오로 시작하기** → 입주
6. [ ] 서로의 우체통에 편지 → 진행률(%)이 오르고 트리에 장식이 달린다
7. [ ] LINE·카카오톡 대화방에 운영 주소를 붙여 넣으면 **제목·설명·그림(집과 우체통)** 미리보기가 뜬다
8. [ ] 로그아웃하면 첫 화면으로 돌아간다

## 9. 함께 걷기 켜기·끄기 (선택 기능, Task 025)

같은 마을에 동시에 접속한 친구의 캐릭터가 서로의 화면에서 걸어 다니는 기능입니다. **기본은 꺼져 있고**, 아래 순서로 켭니다. 꺼져 있을 때는 지금까지와 완전히 같은 화면입니다.

> 💡 환경 변수: 코드 바깥에서 넣어 주는 설정값입니다. 코드를 고치지 않고 기능을 켜고 끌 수 있습니다.

### 켜기 전에 (한 번만)

1. **실제 휴대폰으로 느려지지 않는지 확인합니다.** 방법은 `docs/ROADMAP.md`의 Task 025 "사용자가 직접 해야 하는 일" 1번에 있습니다.
2. **Supabase 실시간 설정을 확인합니다. (권장)**
   1. Supabase 대시보드에서 프로젝트를 엽니다.
   2. 왼쪽 메뉴에서 **Realtime**을 누릅니다.
   3. **Settings**를 누릅니다.
   4. **Allow public access**를 끕니다(회색으로). 그리고 저장합니다.
   - 이 설정은 "아무나 들어올 수 있는 공개 채널"을 허락하는 스위치입니다. 우리는 주민만 들어오는 비공개 채널만 쓰므로 꺼 두는 것이 안전합니다. 켜 둔 상태에서도 엿듣기가 안 되는 것은 확인했습니다.

### 켜는 법

1. 코드가 GitHub에 올라가 있어야 합니다(1번).
2. Vercel → 프로젝트 → **Settings → Environment Variables**로 갑니다.
3. 이름(Key)에 `LIVE_WALK`, 값(Value)에 `1`을 넣습니다. 적용 범위는 **Production**에 체크합니다.
4. **Save**를 누릅니다.
5. Vercel → **Deployments** → 가장 위(최신) 배포의 `⋯` → **Redeploy**를 누릅니다. (환경 변수는 다시 배포해야 적용됩니다)
6. 배포가 끝나면 휴대폰 2대(또는 휴대폰과 컴퓨터)에서 서로 다른 계정으로 같은 마을에 들어가 확인합니다.
   - [ ] 상대 캐릭터가 이름표와 함께 보인다
   - [ ] 내가 땅을 누르면 상대 화면에서 내 캐릭터가 같은 곳으로 걸어간다
   - [ ] 상대 집 이름표에 초록 점(접속 중)이 붙는다
   - [ ] 한쪽이 창을 닫으면 곧 사라진다
   - [ ] 다른 앱으로 갔다가 10초 넘어 돌아와도 다시 보인다

### 끄는 법 (두 가지)

- **보통**: Vercel → Settings → Environment Variables에서 `LIVE_WALK`를 지우고(또는 값을 `0`으로) **Redeploy**. 다시 배포가 끝나면 꺼집니다.
- **급할 때 (다시 배포 없이 바로)**: Supabase 대시보드 → **SQL Editor**에 아래 두 줄을 붙여 넣고 실행합니다. 채널에 아무도 들어올 수 없게 되어 기능이 멈춥니다. 걷기·편지 등 다른 기능은 그대로입니다.

  ```sql
  drop policy "마을 주민만 실시간 채널 듣기" on realtime.messages;
  drop policy "마을 주민만 실시간 채널 보내기" on realtime.messages;
  ```

  - 이미 접속해 있는 사람은 다시 연결할 때부터 막힙니다.
  - 다시 살리려면 `supabase/migrations/20261128000000_07_live_walk.sql` 아래쪽의 `create policy` 두 개를 SQL Editor에서 실행합니다.

### 사용량 보는 곳

무료 요금제 한도는 **동시 연결 200개, 초당 100 메시지, 한 달 200만 메시지**입니다. 시험에서는 5명이 3초마다 계속 눌러도 초당 8개 정도였습니다.

- Supabase 대시보드 → 프로젝트 → **Reports → Realtime**: 연결 수와 메시지 수의 흐름
- Supabase 대시보드 → 조직(Organization) → **Usage**: 이번 달 누적 "Realtime Messages", "Realtime Peak Connections"
- (메뉴 이름은 대시보드가 바뀌면서 조금 달라질 수 있습니다. "Realtime"과 "Usage"를 찾으면 됩니다)
- 월 사용량이 한도의 절반을 넘기 시작하면 알려 주세요. 방송 간격(`lib/village/liveProtocol.ts`의 `LIVE_BUDGET_PER_SECOND`)을 조정할 수 있습니다.

### 알아 둘 점 (지인에게 설명할 때)

- 한 화면에 보이는 다른 사람은 **가까운 30명까지**입니다(Task 026에서 8명 → 25명 → 30명. 25명까지는 실제 휴대폰에서 확인, 30명은 확인 대기). 그보다 많으면 나머지는 집 이름표의 초록 점으로만 보입니다.
- 사람이 많은 마을(20명 이상)에 들어가면, 먼저 와 있던 사람들이 한꺼번에가 아니라 **10~17초에 걸쳐 차례로** 나타납니다. 메시지가 한순간에 몰리지 않게 한 것이고 고장이 아닙니다.
- 전파가 끊기거나 앱이 갑자기 꺼진 사람은 **최대 1분쯤 마지막 자리에 서 있는 모습**으로 남을 수 있습니다. 고장이 아닙니다.
- 지금은 모두 같은 모습의 캐릭터입니다(꾸미기 반영은 다음 작업).
- 실시간 연결이 안 되는 날에도 걷기와 편지는 그대로 됩니다. 다른 사람이 보이지 않을 뿐입니다.
